# UL-55 clean-room qualification

Date: 2026-08-24

This report qualifies the base, response-only `ul probe` smoke contract against one ordinary Python
callable and one bearer-authenticated synchronous JSON endpoint. Both targets are disposable and
local. The single JSONL record contains a response genuinely observed from both fixtures; no
production endpoint, customer data, lifecycle hook, trace integration, state hook, or customer
evaluator is involved.

## Result

| Measure | Callable | Authenticated HTTP |
| --- | ---: | ---: |
| Grounded cases | 1 | 1 |
| Commands after dependency install | 1 | 2 (server + probe) |
| UL config or adapter code written by operator | 0 | 0 |
| Dataset/report/reset/snapshot code written by operator | 0 | 0 |
| Smoke target calls | 1 | 1 |
| Smoke semantic calls | 0 | 0 |
| Measured automated journey wall time | 0.55 seconds | 0.98 seconds |
| Evidence level | Response only | Response only |
| Trajectory conclusion | Unavailable | Unavailable |
| Committed-state conclusion | Unavailable | Unavailable |

The measurements above include the public CLI subprocess and, for HTTP, fixture shutdown. Both
smoke journeys are well below the five-minute threshold. They measure machine execution after the
locked environment exists; the command count and operator-authored-code rows separately expose the
human setup burden. The under-fifteen-minute finding threshold remains gated below.

The smoke output made the distinction reviewers need: the live response was observed, while
trajectory evidence and committed-state verification were unavailable. It did not present either
unavailable channel as passed. Before any semantic request, the campaign receipt displayed three
total target requests including smoke, up to eight semantic calls, completion-token and wall-time
bounds, and that monetary cost was unknown and unbounded without trusted pricing.

## Finding gate

The repository environment used for this qualification had no semantic-provider credential. The
paid/network campaign was therefore deliberately declined, and no live finding or live finding
comprehension time is claimed. The executable test covers the zero-semantic-call smoke boundary;
existing campaign tests cover drift, sensitivity, instability, and inconclusive reporting with a
deterministic semantic fixture, but that is not substituted for a live clean-room finding.

UL-55 is only fully qualified after an operator with a dedicated semantic-provider credential runs
one of the fixture journeys through the displayed bounded campaign and records the time to first
finding plus reviewer comprehension. The secret must remain in the operator environment and out of
this report and all receipts.

## Reproduction

Follow [`examples/probe_qualification/README.md`](../../examples/probe_qualification/README.md).
The automated smoke proof is:

```bash
tmp/venv/bin/pytest examples/probe_qualification/tests/test_qualification.py -q
```

The fixtures are deterministic, secret-free, and use only loopback HTTP. Runtime receipts and UL
evidence remain ignored private files.

The HTTP fixture follows the standard bearer `Authorization` request shape from
[RFC 6750](https://www.rfc-editor.org/rfc/rfc6750) but is deliberately implemented with Python's
[development-only HTTP server](https://docs.python.org/3/library/http.server.html). It is not a
production-server example.
